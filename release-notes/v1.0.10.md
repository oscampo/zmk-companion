# ZMK Companion v1.0.10

## Highlights

- **Fixed: Apply could crash if two tracked leagues shared the same short name.** The unregistered-team warning added in v1.0.9 (`WarnAboutUnregisteredSportsTeams`) grouped leagues by their `ShortName`, ESPN's own per-league abbreviation, assuming it was unique. It isn't: the league picker only prevents adding the same ESPN path twice, not the same abbreviation, so two different leagues (commonly two minor soccer leagues from different countries) sharing one crashed the entire Apply with an unhandled exception, not just the warning. Found via code review, not a user report, and confirmed and fixed on a real install: two leagues forced to share a short name no longer crash Apply, and a token matching either of the colliding leagues' tracked teams still resolves correctly instead of rendering blank.

## Requirements

- Windows 10, build 19041 or later
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- A ZMK keyboard with the display GATT service enabled, see [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md#firmware) for what that requires. Not supported on stock ZMK firmware.

## Install

Download `ZmkCompanion-Setup-1.0.10.exe` below and run it, no admin rights needed. The installer isn't code-signed, so Windows SmartScreen will flag it as an unrecognized publisher on first run, that's expected for an indie/open-source tool without a paid certificate, not a sign of anything malicious, click "More info" → "Run anyway" to proceed. Full walkthrough in [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md).

## Known limitations

- Random page flashing / erratic rendering after reconnecting is still unresolved, same status as v1.0.6 through v1.0.9. The only workaround confirmed to work consistently is power-cycling both halves of the keyboard.
- If ESPN tightens its API blocking again (a WAF change on their side, not something under this project's control), sports tokens could go silent again, this time the failure will at least be visible in the debug log.
- The display firmware is currently written for one reference keyboard (eyelash_corne). It should work on any ZMK board using a `nice_view` display, but that hasn't been verified on hardware other than the reference board yet, see [zmk-companion-template](https://github.com/oscampo/zmk-companion-template) if you'd like to try it and report back.
- Auto-start scripts are only reliably portable (export/import, and the shipped demo script) when they live in `%LOCALAPPDATA%\ZmkCompanion\scripts\`, a command referencing a script elsewhere on disk can't be detected and bundled automatically.
- `clients/cli` and `clients/ios` (older Python scripts) only speak the legacy plain-text display characteristic, not this app's current cell-grid/bitmap protocol.
