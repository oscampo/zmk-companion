# ZMK Companion v1.0.7

## Highlights

- **New: reorder display pages directly in the editor.** Previously the only way to change the order pages cycle through was deleting and re-adding them from scratch. The Pages section of the Display Editor now has ▲/▼ buttons next to the page selector that swap the current page with its neighbor, same interaction the row list already used.
- **New: duplicate a display page.** A "Duplicate" button (between Name and Dur. in the Pages section) copies the currently selected page, rows and all settings included, into a new page right after it, and switches to editing the copy. Useful for reusing a page's layout as a starting point instead of rebuilding it row by row.

## Requirements

- Windows 10, build 19041 or later
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- A ZMK keyboard with the display GATT service enabled, see [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md#firmware) for what that requires. Not supported on stock ZMK firmware.

## Install

Download `ZmkCompanion-Setup-1.0.7.exe` below and run it, no admin rights needed. The installer isn't code-signed, so Windows SmartScreen will flag it as an unrecognized publisher on first run, that's expected for an indie/open-source tool without a paid certificate, not a sign of anything malicious, click "More info" → "Run anyway" to proceed. Full walkthrough in [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md).

## Known limitations

- Random page flashing / erratic rendering after reconnecting is still unresolved, same status as v1.0.6. The only workaround confirmed to work consistently is power-cycling both halves of the keyboard.
- If ESPN tightens its API blocking again (a WAF change on their side, not something under this project's control), sports tokens could go silent again, this time the failure will at least be visible in the debug log.
- The display firmware is currently written for one reference keyboard (eyelash_corne). It should work on any ZMK board using a `nice_view` display, but that hasn't been verified on hardware other than the reference board yet, see [zmk-companion-template](https://github.com/oscampo/zmk-companion-template) if you'd like to try it and report back.
- Auto-start scripts are only reliably portable (export/import, and the shipped demo script) when they live in `%LOCALAPPDATA%\ZmkCompanion\scripts\`, a command referencing a script elsewhere on disk can't be detected and bundled automatically.
- `clients/cli` and `clients/ios` (older Python scripts) only speak the legacy plain-text display characteristic, not this app's current cell-grid/bitmap protocol.
