# ZMK Companion v1.0.8

## Highlights

- **Fixed: the installer could duplicate or wipe the user's PATH.** Found by a user auditing why their PATH had this app's install directory duplicated 18 times. The `[Registry]` entry that added the install directory to PATH had no check for whether it was already present, so every reinstall or silent auto-update run appended it again. Worse, it used `uninsdeletevalue` on the shared `Path` registry value itself, which meant a normal uninstall would delete the user's **entire** PATH, not just this app's fragment, a bug that hadn't been triggered yet only because nobody had uninstalled. Both are fixed: installing is now idempotent (checks before adding), and uninstalling removes only this app's own directory, verified on a real Windows machine against a PATH with 60+ pre-existing entries, all of which survive an install/uninstall cycle untouched.

## Requirements

- Windows 10, build 19041 or later
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- A ZMK keyboard with the display GATT service enabled, see [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md#firmware) for what that requires. Not supported on stock ZMK firmware.

## Install

Download `ZmkCompanion-Setup-1.0.8.exe` below and run it, no admin rights needed. The installer isn't code-signed, so Windows SmartScreen will flag it as an unrecognized publisher on first run, that's expected for an indie/open-source tool without a paid certificate, not a sign of anything malicious, click "More info" → "Run anyway" to proceed. Full walkthrough in [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md).

If you installed an earlier version and already have duplicate `ZmkCompanion` entries in your user PATH from the old bug, this update does not clean those up automatically, it only stops adding new ones. Remove the extras by hand via `[Environment]::SetEnvironmentVariable("Path", ..., "User")` or the System Properties PATH editor if it bothers you, they're harmless duplicates, not a functional problem.

## Known limitations

- Random page flashing / erratic rendering after reconnecting is still unresolved, same status as v1.0.6/v1.0.7. The only workaround confirmed to work consistently is power-cycling both halves of the keyboard.
- If ESPN tightens its API blocking again (a WAF change on their side, not something under this project's control), sports tokens could go silent again, this time the failure will at least be visible in the debug log.
- The display firmware is currently written for one reference keyboard (eyelash_corne). It should work on any ZMK board using a `nice_view` display, but that hasn't been verified on hardware other than the reference board yet, see [zmk-companion-template](https://github.com/oscampo/zmk-companion-template) if you'd like to try it and report back.
- Auto-start scripts are only reliably portable (export/import, and the shipped demo script) when they live in `%LOCALAPPDATA%\ZmkCompanion\scripts\`, a command referencing a script elsewhere on disk can't be detected and bundled automatically.
- `clients/cli` and `clients/ios` (older Python scripts) only speak the legacy plain-text display characteristic, not this app's current cell-grid/bitmap protocol.
