# ZMK Companion v1.0.9

## Highlights

- **Fixed diagnostic blind spot: sports tokens for a specific team could go blank with zero visibility into why.** `{sports.next_game:NFL.GB}` and similar per-team tokens rendered blank with nothing in the debug log to explain it. Root cause in this instance was a settings reset that had wiped the NFL tracked-teams list, not a fetch or season-crossing bug, but the old log only showed a count (`pendingAfterInitial=0`), which couldn't distinguish "this team was never requested" from "it was requested and never resolved". The log now prints the actual `targets`/`pending` lists, so that distinction is visible immediately instead of requiring guesswork.
- **Added: a warning when a page references a team that isn't tracked.** Until now, referencing an untracked team in a page template (e.g. `{sports.last_game:NFL.GB}` with an empty NFL teams box) failed silently, the row just rendered blank with no indication why. Clicking Apply now scans every page's templates for `{sports.*:LEAGUE.TEAM}` tokens and checks each one against that league's tracked-teams list. If a token references a team that isn't tracked, a dialog names the exact page, league, and team so it can be fixed on the spot. This does not block Apply, the row still renders blank exactly as before, it only adds an explanation.

## Requirements

- Windows 10, build 19041 or later
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- A ZMK keyboard with the display GATT service enabled, see [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md#firmware) for what that requires. Not supported on stock ZMK firmware.

## Install

Download `ZmkCompanion-Setup-1.0.9.exe` below and run it, no admin rights needed. The installer isn't code-signed, so Windows SmartScreen will flag it as an unrecognized publisher on first run, that's expected for an indie/open-source tool without a paid certificate, not a sign of anything malicious, click "More info" → "Run anyway" to proceed. Full walkthrough in [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md).

## Known limitations

- Random page flashing / erratic rendering after reconnecting is still unresolved, same status as v1.0.6 through v1.0.8. The only workaround confirmed to work consistently is power-cycling both halves of the keyboard.
- If ESPN tightens its API blocking again (a WAF change on their side, not something under this project's control), sports tokens could go silent again, this time the failure will at least be visible in the debug log.
- The display firmware is currently written for one reference keyboard (eyelash_corne). It should work on any ZMK board using a `nice_view` display, but that hasn't been verified on hardware other than the reference board yet, see [zmk-companion-template](https://github.com/oscampo/zmk-companion-template) if you'd like to try it and report back.
- Auto-start scripts are only reliably portable (export/import, and the shipped demo script) when they live in `%LOCALAPPDATA%\ZmkCompanion\scripts\`, a command referencing a script elsewhere on disk can't be detected and bundled automatically.
- `clients/cli` and `clients/ios` (older Python scripts) only speak the legacy plain-text display characteristic, not this app's current cell-grid/bitmap protocol.
