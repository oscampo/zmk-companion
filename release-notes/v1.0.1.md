# ZMK Companion v1.0.1

## Highlights

- **Demo Canvas out of the box**. a fresh install now ships with a 5-page
  Canvas (Welcome, Posibilities, Weather, Data from APIs, End) already
  cycling, plus a ready-to-run Auto-start script (Dow Jones, USD/local
  exchange rate, current #1 Spotify track, no Python dependency) instead of
  a single blank clock page.
- **Auto-start tied to the loaded Canvas**. Library presets now carry their
  own Auto-start entries alongside their pages. Loading a different preset
  (a "Sports" Canvas vs. an "Economics" one, say) stops every script the
  previous one had running and starts only the ones checked in the new
  one, so switching Canvas doesn't leave two scripts feeding the same
  token at once.
- **Export / Import settings**. tray menu items to bundle `settings.json`,
  every Library preset, and your Auto-start `scripts\` folder into one
  `.zip`, for moving your whole setup between two machines (work/home PC).
- **Update notifications**. checks GitHub's Releases page once per launch
  and lets you know if a newer version is out, via a tray balloon you can
  click to open the download page. Nothing downloads or installs
  automatically. Also available on demand from the tray's "Check for
  updates…".
- **Jump to a Canvas page on demand**. `Ctrl+Alt+Shift+Win+1` through `+9`
  jump straight to page 1-9, wherever the auto-cycle currently is.
- **Auto-start scripts run on the app's own startup**, not just at Windows
  login, so closing and reopening ZmkCompanion.exe (after an update, say)
  re-runs them instead of leaving their last output stale.
- **`{ext.text}` full-screen text survives page cycling** and gets
  pre-cached even while a different page is active, instead of showing a
  stale, tier-clipped render the first time its page comes back around.
- **Firmware is now a proper west module**
  ([`oscampo/zmk-companion`](https://github.com/oscampo/zmk-companion),
  `firmware/`), installable directly from any `zmk-config`'s `west.yml`,
  no fork or copied files needed. The enabling flag is renamed
  `CONFIG_ZMK_COMPANION_DISPLAY` (from the unnamespaced
  `CONFIG_KBD_BLE_DISPLAY`), see the upgrade note below if you have an
  existing fork.

## Upgrading an existing fork

If your `zmk-config` predates this release and still sets
`CONFIG_KBD_BLE_DISPLAY=y` anywhere, that line is now a silent no-op, the
build still succeeds but ships without the display. Update it to
`CONFIG_ZMK_COMPANION_DISPLAY=y` and add the `oscampo/zmk-companion`
module entry to your `west.yml`, see
[`docs/getting_started.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/getting_started.md#1-firmware-one-time).

## Requirements

- Windows 10, build 19041 or later
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- A ZMK keyboard with the display GATT service enabled, see
  [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md#firmware)
  for what that requires. Not supported on stock ZMK firmware.

## Install

Download `ZmkCompanion-Setup-1.0.1.exe` below and run it, no admin rights
needed. The installer isn't code-signed, so Windows SmartScreen will flag
it as an unrecognized publisher on first run, that's expected for an
indie/open-source tool without a paid certificate, not a sign of anything
malicious, click "More info" → "Run anyway" to proceed. Full walkthrough in
[`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md).

## Known limitations

- The display firmware is currently written for one reference keyboard
  (eyelash_corne). It should work on any ZMK board using a `nice_view`
  display, but that hasn't been verified on hardware other than the
  reference board yet, see
  [zmk-companion-template](https://github.com/oscampo/zmk-companion-template)
  if you'd like to try it and report back.
- Auto-start scripts are only reliably portable (export/import, and the
  shipped demo script) when they live in
  `%LOCALAPPDATA%\ZmkCompanion\scripts\`, a command referencing a script
  elsewhere on disk can't be detected and bundled automatically.
- `clients/cli` and `clients/ios` (older Python scripts) only speak the
  legacy plain-text display characteristic, not this app's current
  cell-grid/bitmap protocol.
