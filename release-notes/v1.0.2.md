# ZMK Companion v1.0.2

## Highlights

- **Sports tokens split into league-wide vs. per-team.** `{sports.next_game:NFL}`
  (and its `_date`/`_gametime`/`_last_*` siblings) now show the **NFL's**
  next game in general, not your configured team's. To get a specific
  team's game, add it to the token: `{sports.next_game:NFL.GB}`.
- **Multiple favorite teams per league.** The team field on the Sports tab
  now takes a comma-separated list (`GB,KC`), each getting its own
  independent set of tokens (`NFL.GB`, `NFL.KC`, ...) and its own entry in
  the token picker.
- Fetching stays efficient regardless of how many teams you track: a single
  paginated walk per league resolves the league-wide game and every team's
  game together, instead of repeating the walk once per team.

## ⚠️ Breaking change

If you already had a team configured for a league, any row using the bare
`{sports.*}` tokens *without* a team qualifier, or the `{sports.*:<league>}`
form (e.g. `{sports.next_game:NFL}`), was showing **your team's** game.
Starting in this release, those same tokens show the **league's** game in
general. To keep showing your team specifically, update those rows to the
new `{sports.*:<league>.<team>}` form, e.g. `{sports.next_game:NFL.GB}`.

There is no automatic migration — existing Canvas pages using the old
team-filtered tokens will silently start showing different content after
updating. Check any Sports row on your Canvas after installing this version.

## Requirements

- Windows 10, build 19041 or later
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- A ZMK keyboard with the display GATT service enabled, see
  [`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md#firmware)
  for what that requires. Not supported on stock ZMK firmware.

## Install

Download `ZmkCompanion-Setup-1.0.2.exe` below and run it, no admin rights
needed. The installer isn't code-signed, so Windows SmartScreen will flag
it as an unrecognized publisher on first run, that's expected for an
indie/open-source tool without a paid certificate, not a sign of anything
malicious, click "More info" → "Run anyway" to proceed. Full walkthrough in
[`docs/user_guide.md`](https://github.com/oscampo/zmk-companion/blob/main/docs/user_guide.md).

## Known limitations

- The display firmware is currently written for one reference keyboard
  (eyelash_corne). It should work on any ZMK board using a `nice_view`
  display, but that hasn't been verified on hardware other than the
  reference board yet, see
  [zmk-companion-template](https://github.com/oscampo/zmk-companion-template)
  if you'd like to try it and report back.
- Auto-start scripts are only reliably portable (export/import, and the
  shipped demo script) when they live in
  `%LOCALAPPDATA%\ZmkCompanion\scripts\`, a command referencing a script
  elsewhere on disk can't be detected and bundled automatically.
- `clients/cli` and `clients/ios` (older Python scripts) only speak the
  legacy plain-text display characteristic, not this app's current
  cell-grid/bitmap protocol.
